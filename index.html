The flow

From template to installer

No local toolchain. The first push is the build trigger; the fallback is one button.

1

Copy the template

Create your own repository. The Windows build workflow comes with it.

2

Edit config.json

Set the title, one or two pane URLs, the allowed domains, and the layout.

3

Commit

The push builds your MSI and NSIS. If no run appears, use Actions → Run workflow.

Agent handoff

Let an agent do the copy and config.

Paste this into a coding agent. It reads the maintainer guide, asks for your apps, and walks you through the first build.

Copy the open-source template at https://github.com/Spuds0588/Powerapp-Frontline-Workspace-Shell and help me turn it into a Windows desktop shell for my web apps. Read agents.md and config.json first. Ask me for the window title, the one or two app URLs, the domains they need, the sidebar side and width, and whether I want kiosk mode. Then update config.json and walk me through committing so GitHub Actions builds my MSI and NSIS. If no build starts, use Run workflow in Actions.
Try the build

Install the demo profile

An unsigned Windows build that opens the dispatch pairing. It works without a tenant, an account, or a login.

The installer is a real Tauri build, not a mockup. The demo profile embeds the Power Apps dashboard and Teams recap shown above, so you can judge the window, the dual-pane resize, and the supervisor exit on Windows.

Use Ctrl+Shift+Q to quit, including in kiosk mode. SmartScreen may warn because the build is not code-signed.
