What it does

Two panes, one window

Run a Power App beside Teams, a dialer, or a second app. Dock the sidebar left or right, set its width, or use single mode when one pane is enough.

A hard domain boundary

Every navigation is checked against allowedDomains. Apex domains and their subdomains pass; everything else is blocked and logged.

Kiosk when it matters

Borderless fullscreen, no decorations, no resize. The supervisor exit is Ctrl+Shift+Q, registered outside the remote page.

Nothing to install beside it

config.json is embedded at build time. Distribute one .msi or .exe; there is no loose config to edit, lose, or tamper with.

From template to installer

No local Rust or C++ build chain. The Windows runner in GitHub Actions does the packaging.

Copy the template. Use the button above. The new repository is yours, and the workflow comes with it.

Edit config.json. Set the title, pane URLs, allowed domains, and layout. Commit the change.

Let Actions build. The commit starts Build Enterprise Desktop Shell. No run? Open Actions in your repository and choose Run workflow.

Download the artifact. In the latest green run, download FrontlineShell-Windows-Installer and run the .msi or -setup.exe.

Installers are artifacts, not releases. This template does not publish a GitHub Release. The public run linked above is the default config; your copy builds your own. A cold copy builds in about six minutes; later builds are faster. To test the shell without a tenant, run the workflow with config: demo; it embeds the demo profile and the same artifact name.

One file to configure

config.json is the whole control surface: window size, kiosk mode, the domain boundary, the split, and the two URLs.

Invalid JSON fails the build before an installer exists. A missing required key does too, so a typo cannot ship as a broken app.

The example below shows a dual-pane configuration with Power Apps and Teams.

{
  "title": "Frontline Operations Console",
  "kioskMode": false,
  "allowedDomains": [
    "apps.powerapps.com",
    "teams.microsoft.com",
    "login.microsoftonline.com"
  ],
  "layout": {
    "mode": "dual",
    "sidebarPosition": "right",
    "sidebarWidth": 460
  },
  "panes": {
    "primary":   { "url": "https://apps.powerapps.com" },
    "secondary": { "url": "https://teams.microsoft.com" }
  }
}

Abridged example. The full schema is in the product spec.

Deliberately small

No scraping or DOM rewriting

The shell orchestrates windows and enforces the boundary. Its only injected script suppresses the context menu; it does not read or alter the hosted page.

No runtime settings

No settings panel, database, updater, or telemetry. Change the config in the repo and build again.

One supported target

Windows 10/11 on WebView2, packaged as MSI and NSIS. Keep the template lean instead of pretending to be cross-platform.
